ALPHA SWAP — PROVIDER BTC ↔ LIGHTNING

OBIETTIVO

Il modulo Alpha Swap è già predisposto con LI.FI per gli swap EVM/cross-chain.

Ora dobbiamo completare la parte fondamentale:

BTC Mainnet ↔ BTC Lightning

Questa funzionalità NON deve rimanere uno stub indefinitamente.

Prima di implementare qualsiasi cosa, eseguire una ricerca tecnica aggiornata e verificabile per identificare il miglior provider disponibile per Alpha Wallet.

3. FEE ALPHA

Alpha deve mantenere il modello:

Alpha Fee = 0,25% = 25 BPS

La fee deve essere configurabile dall’Admin tramite:

ALPHA_SWAP_FEE_BPS

NON hardcodare la fee.

Verificare specificamente per il provider BTC/Lightning scelto:

È tecnicamente possibile applicare una commissione Alpha del 0,25% in modo trasparente e non-custodial?

Se sì:

documentare esattamente come.

Se no:

NON inventare workaround.

Indicare chiaramente il limite.

⸻

4. NON TOCCARE PAYMENT LOGIC

Questa è una regola assoluta.

NON modificare:

* BTC send esistente;
* BTC receive;
* UTXO selection;
* BTC fee logic;
* RBF;
* Lightning payment logic esistente;
* WalletConnect;
* ThirdWeb;
* signing flow;
* polling;
* deposit detection;
* payment history;
* balance logic.

Il nuovo provider deve essere implementato esclusivamente dentro:

SwapProvider

/ adapter dedicato.

Esempio:

BitcoinLightningSwapProvider

Lo Swap deve rimanere completamente isolato.

⸻

5. ARCHITETTURA

L’architettura deve rimanere:

Alpha Swap Engine
        |
        +---- LiFiSwapProvider
        |
        +---- BitcoinLightningSwapProvider

La UI non deve sapere quale provider viene utilizzato.

Per:

BTC → Lightning

il router seleziona:

BitcoinLightningSwapProvider

Per:

Lightning → BTC

stesso provider.

In futuro deve essere possibile sostituire il provider senza modificare:

* UI;
* state machine;
* Admin;
* Swap History.

⸻

6. NON IMPLEMENTARE ANCORA SE IL PROVIDER NON È VERIFICATO

Se durante la ricerca emerge che un provider non è realmente disponibile, non-custodial o non supporta entrambe le direzioni:

NON implementarlo semplicemente perché era già presente nello stub.

Lo stub attuale può essere mantenuto.

Prima scegliere il provider corretto.
