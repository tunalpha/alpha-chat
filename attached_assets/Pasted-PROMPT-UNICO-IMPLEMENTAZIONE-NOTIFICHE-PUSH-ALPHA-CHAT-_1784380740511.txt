OBIETTIVO

Implementare un sistema completo di Web Push Notifications senza modificare l’architettura della chat.

Le Push devono essere un sistema completamente indipendente.

Il WebSocket continuerà ad essere il canale realtime.

Le Push serviranno solo quando:

* browser in background
* schermo spento
* PWA installata
* websocket disconnesso
* browser chiuso (nei limiti della piattaforma)

⸻

ARCHITETTURA OBBLIGATORIA

Implementare un layer separato.

Message Service
        │
        │
        ├────────────► WebSocket
        │                 │
        │                 ▼
        │            Chat aperta
        │
        │
        └────────────► Push Notification Service
                              │
                              ▼
                      Web Push (VAPID)
                              │
                              ▼
                     Service Worker
                              │
                              ▼
                       Notification API

Il Message Service NON deve sapere come funziona il push.

Deve solamente emettere un evento.

⸻

Mai inserire codice Push dentro:

* ChatPage

message.received

call.missed

Il Push Service ascolta questi eventi.

Mai il contrario.

PERFORMANCE

Le Push NON devono rallentare:

messaggi

Signal

decrypt

encrypt

WebSocket

chiamate

typing

Ogni invio Push deve essere asincrono.

Mai attendere il completamento dell’invio Push durante la gestione del messaggio.

Utilizzare un dispatcher o una coda asincrona in modo che un errore nell’invio della notifica non possa bloccare o ritardare il flusso della messaggistica.

⸻

MODALITÀ DI SVILUPPO

Prima di scrivere codice:

1. Analizzare l’architettura esistente.
2. Individuare eventuale codice già presente riutilizzabile.
3. Elencare tutti i file da creare.
4. Elencare tutti i file da modificare.
5. Motivare ogni modifica.
6. Spiegare perché ogni modifica non può introdurre regressioni nella messaggistica.

Se una modifica coinvolge componenti condivisi con il flusso dei messaggi, fermarsi e chiedere conferma.

⸻

OBIETTIVO FINALE

Realizzare un sistema di notifiche push completamente disaccoppiato dalla logica della chat, basato su eventi, con responsabilità separate e senza alterare il comportamento dei messaggi o delle chiamate già stabilizzati. Prima produrre un documento tecnico con l’architettura proposta e il piano di implementazione; solo dopo approvazione procedere con il codice.
