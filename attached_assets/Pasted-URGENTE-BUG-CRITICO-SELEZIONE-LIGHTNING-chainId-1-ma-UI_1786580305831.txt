URGENTE — BUG CRITICO SELEZIONE LIGHTNING: chainId -1 ma UI mostra dati BNB/EVM

Ho fatto il test reale su iPhone.

Quando seleziono Lightning, il selettore mostra:

Chain -1

QUINDI il filtro riconosce correttamente chainId = -1.

MA LA UI SOTTO È SBAGLIATA:

Mostra:

Saldo totale
0 BNB

e:

Il tuo indirizzo EVM
0x04631A6e863718a8F4c21c2ce1303e30dC87B298

Questo NON deve mai accadere quando Lightning è selezionato.

ROOT CAUSE DA CERCARE:

Il selected chain state cambia a chainId = -1, ma il componente del portfolio continua a utilizzare balance/address/asset data della chain precedente (EVM/BNB).

È quindi un problema di sincronizzazione tra:

selectedChain
chainId = -1
filtered assets
selected chain balance
selected chain address
UI actions

OBIETTIVO:

Quando selectedChain = Lightning / chainId = -1:

1. Mostrare SOLO dati Lightning.

2. Il saldo deve provenire esclusivamente da Spark/Breez:

sparkSat

e NON da:

BNB balance
ETH balance
POL balance
BTC on-chain balance
EVM balance
fallback balance.

3. Il simbolo deve essere:

⚡ BTC

4. Network:

Lightning

5. chainId:

-1

6. Nome:

Bitcoin Lightning

7. NON mostrare un indirizzo EVM 0x....

8. NON mostrare un indirizzo Bitcoin on-chain bc1... come indirizzo Lightning.

9. NON mostrare BNB/ETH/POL come saldo.

10. NON mantenere dati della chain precedente dopo il cambio a Lightning.

11. Se Spark non è connesso o il saldo non è disponibile:

NON mostrare 0 come fallback.

Mostrare invece:

"Lightning non disponibile"

oppure lo stato già previsto:

"⚠️ Dati parziali · Lightning non disponibile"

12. Quando torno da Lightning a Polygon/Ethereum/BNB/Bitcoin:

la UI deve tornare correttamente ai dati della chain selezionata.

IMPORTANTE — SEPARAZIONE BTC:

Bitcoin on-chain:
chainId = 0
network = Bitcoin
asset = BTC
indirizzo = bc1...

Lightning:
chainId = -1
network = Lightning
asset = BTC
saldo = Spark/Breez
NON è Bitcoin on-chain.

NON sommare i due saldi due volte.
