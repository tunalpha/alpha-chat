==================================================
2. STATI PROVIDER
==================================================

Ogni provider deve poter avere uno stato:

ENABLED
DISABLED
FALLBACK

Significato:

ENABLED
→ provider disponibile per essere utilizzato come provider principale.

DISABLED
→ provider completamente escluso dal routing Swap.

FALLBACK
→ provider disponibile esclusivamente come alternativa quando il provider principale non può completare l'operazione.

IMPORTANTE:

FALLBACK NON significa "esegui automaticamente un secondo swap dopo che il primo ha inviato fondi".

NON effettuare MAI un secondo send se il primo provider ha già ricevuto/inviato fondi.

Il fallback automatico deve essere consentito SOLO prima dell'esecuzione irreversibile del pagamento, oppure quando il provider restituisce esplicitamente che nessun deposito è stato effettuato.

Se esiste qualsiasi dubbio sul fatto che i fondi siano già stati inviati:

→ NON fare fallback automatico
→ mantenere lo swap in stato pending/recovery
→ richiedere gestione manuale.

10. FALLBACK — REGOLA CRITICA

NON implementare fallback automatico cieco.

Scenario:

LI.FI riceve BTC
↓
LI.FI/provider ha già ricevuto i fondi
↓
errore

NON chiamare ChangeNOW.

Questo potrebbe causare doppio invio/perdita fondi.

Il fallback automatico può essere utilizzato soltanto quando il provider primario fallisce PRIMA dell'irreversible send.

Definire esplicitamente nel codice uno stato:

FUNDS_COMMITTED = true/false

Se:

FUNDS_COMMITTED = true

→ fallback automatico BLOCCATO.
