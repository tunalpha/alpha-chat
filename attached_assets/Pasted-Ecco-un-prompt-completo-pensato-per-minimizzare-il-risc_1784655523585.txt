Ecco un prompt completo, pensato per minimizzare il rischio di regressioni e mantenere la qualità del codice.

⸻

Implementazione sistema chiamate “WhatsApp-like” (Zero Regressioni)

Obiettivo

Implementare il sistema di chiamate audio/video affinché si comporti come WhatsApp, Signal o FaceTime.

Attualmente una chiamata arriva come una normale notifica push. Deve invece:

* far squillare il telefono anche con app chiusa
* mostrare la schermata nativa di chiamata
* consentire Accetta/Rifiuta
* collegarsi automaticamente alla stanza Daily solo dopo l’accettazione

⸻

REGOLA FONDAMENTALE

NON modificare alcuna logica esistente di:

* autenticazione
* Signal Protocol
* messaggi
* upload media
* Cloudflare R2
* MongoDB
* scheduler
* notifiche messaggi
* encryption
* chat list
* backend media

Le chiamate devono essere implementate come modulo separato.

Se una modifica può generare regressioni, creare nuovi file invece di modificare quelli esistenti.

⸻

FASE 1 — Call State Machine (Backend)

Creare un modulo dedicato.

Stati supportati:

IDLE
↓
CALLING
↓
RINGING
↓
ACCEPTED
↓
CONNECTED
↓
ENDED
↓
MISSED
↓
REJECTED
↓
BUSY
↓
CANCELLED
↓
TIMEOUT

Creare un model MongoDB dedicato:

call_session

con:

* callerId
* receiverId
* conversationId
* roomId Daily
* callType (audio/video)
* state
* startedAt
* answeredAt
* endedAt
* duration
* endReason

FASE 3 — Daily

Quando parte una chiamata:

Creare Room Daily

Inviare Push VoIP

NON entrare nella room.

NON modificare:

* media
* R2
* upload
* scheduler
* auth
* Signal
* encryption
* MongoDB
* notifiche messaggi

Se serve creare nuovi service.

Mai sostituire quelli esistenti.

Performance

Obiettivi:

* Ring < 2 secondi
* Accettazione < 500 ms
* Join Daily < 2 secondi
* Nessun blocco del backend
* Nessuna query MongoDB inutilmente duplicata
* Nessuna regressione TypeScript
* Zero warning
* Zero memory leak

⸻

Consegna finale

Al termine fornire:

* elenco completo dei file creati e modificati;
* motivazione di ogni modifica;
* verifica che nessuna funzionalità esistente sia stata alterata;
* esito di tutti i test di regressione;
* conferma che il backend si avvia senza errori e che il sistema di chiamata è isolato dal resto dell’applicazione.

Importante: procedere in più fasi (backend → notifiche → integrazione Daily → frontend), verificando i test di regressione dopo ogni fase prima di passare alla successiva.
