🔴 PROBLEMI ATTUALI DA RISOLVERE

1 — HISTORY MULTICHAIN

Root cause già identificata:

mc_payment.state_changed

aggiornava la chat ma non chiamava saveTxRecord().

Fix già implementato:

* WS → saveTxRecord()
* mc-history-backfill
* GET /transfers/history
* idempotenza
* authorization sender/receiver
* persistenza IndexedDB

NON riscrivere questa architettura.

Deve rimanere funzionante.

⸻

2 — BSC USDT QUOTE

Problema identificato:

CoinGecko HTTP 429 → cache BSC vuota → PriceUnavailableError → global handler → HTTP 500.

Fix già applicato:

PriceUnavailableError / DynamicFeeError → AppError → HTTP 503

NON modificare ulteriormente questa parte se funziona.

⸻

3 — USDA POLYGON WALLETCONNECT

Problema identificato:

SendPaymentSheet.tsx eseguiva sendTransaction(chainId: 137) senza switchChain(polygon).

Fix applicato:

switchChain(polygon) immediatamente prima di sendTransaction().

NON modificare ulteriormente questa parte se funziona.

⸻

4 — NUOVO PROBLEMA: FIRMA USDT BSC

È stato osservato:

“Errore firma: Please call connect() before request()”

e:

“La transazione potrebbe essere già stata inviata — stiamo verificando.”

Questo NON deve essere risolto cancellando o bypassando la verifica della transazione.

Devi prima determinare:

* perché connect() non è disponibile;
* quale wallet/sessione è attiva;
* quale chain è attiva;
* quale client sta chiamando request();
* se il wallet è effettivamente connesso;
* se la transazione potrebbe essere già stata inviata.

La verifica deve essere idempotente.

NON fare retry ciechi che potrebbero generare doppio pagamento.

⸻

5 — PAGAMENTO USDA E HISTORY

È stato effettuato un pagamento USDA reale.

La chat mostra:

Pagamento completato
1 USDA inviati con successo

MA la transazione non compare nella History.

Questo è ora un TEST REALE DEL FIX HISTORY.

Devi identificare la TX reale generata da quel pagamento e verificare:

txHash
→ backend
→ WS/API
→ IDB
→ History

NON usare fixture per dichiarare questo test superato.

Voglio la TX reale.

⸻

6 — NOTIFICHE: MANCA L’ORARIO

Nella schermata Notifiche viene mostrato:

14 ago

ma manca l’ora.

La History invece mostra data + ora.

Deve diventare:

14 ago · 20:09

usando il timestamp reale già presente nei dati.

IMPORTANTE:

questo è SOLO un problema di rendering.

NON modificare backend/database/blockchain.

NON creare nuovi timestamp lato frontend.

NON alterare il timestamp originale.

⸻

7 — NON MODIFICARE TUTTO INSIEME

Prima di ogni modifica:

individua esattamente il file e la funzione responsabile.

Poi modifica SOLO quella parte.

Dopo ogni modifica:
